# Loan Status Timeline — Product Spec

One rule decides whether a loan is earning. It is implemented once in `shared::loan_status` and used by `GET /v1/loan-book`, `GET /v1/dashboard/summary` (`outstanding_in_loans`, `loan_book_yield`, `current_apy_net_to_splusd`), `GET /v1/financial-position`, `GET /v1/capital-allocation` (`deployed`) and `GET /v1/stats/yield` (`apy` and `accrued`). It replaces the per-endpoint `effective_end` helpers, which ended a loan at its original maturity (#1632, #1535) or never reopened it after a cure (#1592).

- **Source.** `LoanStatusUpdated` events (the contract `StatusUpdated`), read from `params.event.status`. Both arms store the same strings: `Approved`, `Performing`, `WatchList`, `Default`, `Closed`. Contract lifecycle: Approved → Performing (first disburse) ↔ WatchList → Default → (cure) WatchList → … → Closed (final).
- **`status_at(t)`.** The last transition at or before `t`; before the first transition a loan is `Approved`. Closed is final: later transitions are ignored.
- **Active (earning)** = originated (`origination_date ≤ t`) and status at `t` is Approved, Performing or WatchList. Maturity is **not** an end: maturity never changes status, a past-maturity open loan stays active (surfacing as `Past Due` in the Loan Book), and `rollover` only sets a new maturity. A cure (Default → WatchList) makes the loan active again from the cure time.
- **At risk** = status at `t` is WatchList or Default. Default is not active (the outstanding is carved out of the vault into the Pocket) but stays at risk until closed. Default and Closed loans stay visible as Loan Book rows but are excluded from every active-set aggregate.
- **Accrual intervals.** `GET /v1/stats/yield` `accrued` integrates `outstanding(t) × rate(t) / 31_557_600 s` over the loan's active `[from, until)` intervals clipped to the sample time (formula in `book-rate-weighting.md`): it keeps accruing past maturity, stops in Default, resumes after a cure and stops at Close (#1612, #1630, #976). This follows the contract accrual formula except the Default pause: the contract keeps accruing gross interest in Default (`_setDefault` / `_cure` do not advance the epoch; `_accruedInterest` counts the whole time), the API pauses by product decision (#1632) because the loan is carved out of the vault. Known limitation: accrual starts at `origination_date`; a disbursement before it is not accrued until then.
- **Legacy fallback.** A loan with no `LoanStatusUpdated` rows (pre-rework registry) uses its `LoanDefaulted` (→ Default) and `LoanClosed` (→ Closed) events at their timestamps; a loan with no such event keeps its snapshot status from `origination_date`. Rows are read through `ContractLogsRepo::list_loan_lifecycle_events_for_registry` (`LoanStatusUpdated`, `LoanDefaulted`, `LoanClosed`, each with its status), ordered `block_number, log_index` (on-chain order; same-second events keep it).
- **Not in scope.** `financial-position` and `capital-allocation` amounts still use the original senior (+ equity) tranche rather than the outstanding senior. The contract `outstandingTotal` includes a defaulted loan until it is written down; showing it as an impaired asset is not done here.
- **Staging effect.** Loans of the old registry are excluded: every reader, including `/v1/stats/yield` (#1538), reads only the current LoanRegistry's rows, so same-id loans from two registries never share a timeline.
- **Old-registry events.** The old registry (pipeline-contracts@15275ab) emits only `LoanDefaulted` on default and only `LoanClosed` on close; `LoanStatusUpdated` comes only from Performing / WatchList updates. Legacy `LoanDefaulted` / `LoanClosed` rows are therefore always merged into the timeline (Default / Closed at their timestamps, Closed absorbing); on the current registry each directly follows its `LoanStatusUpdated(Default/Closed)` in the same tx, so the merge is a no-op. A loan whose status rows are all unparseable and has no legacy rows falls back to the snapshot status.
- **Known limitation (pre-existing since #1439, out of scope).** The old registry's status enum is numbered Performing=0, WatchList=1, Default=2, Closed=3; old `LoanStatusUpdated` rows and old snapshot statuses decoded with the current mapping read shifted (e.g. WatchList as Performing). Affects at-risk, display and `onchain_status` for old-registry loans only.

# Book Rate and Tenor Weighting — Product Spec

Interest accrues only on outstanding senior (`disbursed − repaid − written_down`) at the current epoch rate (`LoanRegistry` `currentRate`; `EconomicsAmended` / `LoanRolledOver` open a new epoch), so every book-level rate is weighted by outstanding senior, not by original tranche. One shared helper (`shared::book_weighting`) serves `GET /v1/loan-book`, `GET /v1/dashboard/summary` and `GET /v1/stats/yield`.

- **LoanBook `avg_yield` / `weighted_rate`, dashboard `loan_book_yield` / `current_apy_net_to_splusd`:** `Σ(outstanding_senior_i × current_rate_i) / Σ outstanding_senior_i` over the active set (the status-timeline rule in [loan-status-timeline.md](./loan-status-timeline.md): Approved / Performing / WatchList, past maturity included, Default and Closed excluded, a cured loan active again), where `outstanding_senior` is the snapshot's outstanding senior and `current_rate` is the snapshot's full-precision `current_rate_ppm` (ppm, `ONE = 1_000_000`, never floored to bps), falling back to the legacy bps `current_rate × 100`, then to the genesis rate (`senior_interest_rate_ppm`, else `senior_interest_rate_bps × 100`) for pre-rework rows with `current_rate = 0`. The 6-decimal fraction strings (`rate`, `avg_yield`) hold the exact ppm (6 dp = 1 ppm). `null` when Σ outstanding is 0 (undisbursed loans weigh 0). The net APY applies the effective haircut to this gross rate. The per-loan `rate` column is the same current rate.
- **`avg_duration_days` / `weighted_tenor_days`:** weighted by outstanding senior; tenor is the current full term `current_maturity − origination` (rollover-aware, falling back to the original maturity when the current one is absent). The per-loan `duration_days` column uses the same term.
- **`/v1/stats/yield` `apy` series:** at each sample `t`, over loans active at `t` (same rule), weight by `outstanding(t)` (the `outstanding` of the loan's latest `Disbursed` / `Undisbursed` / `PaymentRecorded` / `PaymentUnrecorded` / `LoanDefaulted` / `LoanWrittenDown` event at or before `t`, else 0) and use the rate in force at `t` (genesis rate updated by `EconomicsAmended` / `LoanRolledOver` `new_rate` at or before `t`, in ppm and untruncated, e.g. 112,550 stays 112,550, so `/v1/loan-book` and `/v1/stats/yield` agree). `apy` is the outstanding-weighted mean ppm / 1,000,000. `null` when Σ outstanding(t) is 0.  Loans from the pre-rework registry have no outstanding-bearing events (they were fully drawn at `LoanDrawn`), so they weigh 0 and the series `apy` is `null` while only such loans are active. The series is scoped to the current LoanRegistry (#1538), so these loans are excluded.
- **`/v1/stats/yield` `accrued`:** the contract gross accrual model (#1612). Per loan, `∫ outstanding(t) × rate_ppm(t) dt / (1_000_000 × YEAR)` over the loan's active intervals clipped to the sample time, summed over loans; `YEAR = 31_557_600` s (365.25 d, `shared::book_weighting::CONTRACT_YEAR_SECS`), simple interest, no maturity cap; stops in Default, resumes after a cure, stops at Close. The accrual follows the contract formula except the Default pause: the contract keeps accruing gross interest in Default (`_setDefault` / `_cure` do not advance the epoch and `_accruedInterest` counts the whole time), while the API pauses in Default by product decision (#1632) because the loan is carved out of the vault. `outstanding(t)` and `rate_ppm(t)` are the `apy` definitions above; each active interval is split at every outstanding / rate event so both are piecewise constant (`shared::book_weighting::LoanAccrual`: breakpoints and a cumulative integral are built once per loan, so each sample costs a binary search per interval; `accrued_over_intervals` is the one-shot form). Same-timestamp events apply in on-chain order (`ORDER BY block_number, log_index`), the last winning; Stellar event `outstanding` is normalised to base-6 by `normalise_rate_events`. The waterfall (`yield.md` § Waterfall components) shares the contract year and `LoanAccrual`, but unlike this endpoint it accrues through Default and stays in raw on-chain units (#1630); its gross interest floors once per contract epoch (`LoanAccrual::accrued_floored_per_segment`), where a `LoanDefaulted` breakpoint does not open an epoch (#2126). Old-registry loans are excluded: every `/v1/stats/yield` reader is scoped to the current LoanRegistry (#1538).

## Scope

Build the Trustee **Origination detail / review** page — the destination opened
by clicking a row in the #813 Origination table. Figma node `4116:9292`
(artifacts in `/tmp/figma-orig-detail/`).

In scope:

1. A new dynamic route `packages/trustee/src/routes/origination.$loanId.tsx`
   (TanStack Router file route; the route tree is auto-generated by the Vite
   `TanStackRouterVite` plugin — no manual `routeTree.gen.ts` edits).
2. Make the #813 table **rows** clickable (keyboard-activatable, proper role) →
   navigate to the detail route, passing the clicked `SubmissionView`
   (`loan_data` + `id` + `status` + `documents`) via router navigation state.
   The existing inert "Review" button stays **as-is** (per human direction —
   do NOT wire it for navigation). Change is to
   `packages/trustee/src/routes/origination.tsx`.
3. A trustee-local collateral-valuation hook
   (`packages/trustee/src/api/useCollateralValuation.ts`) via `apiFetch`
   (no `@pipeline/frontend` import), Stellar-scoped (`chain_id=99000001`),
   typed to the backend `CollateralValuationResponse`.

   chips, **Loan Terms** card, **Deal Details** card, full-width **Collateral
   valuation — <mode>** card, footer note + three inert action buttons.
5. A view-model hook (`origination.$loanId-detail.ts` colocated, per
   `docs/FRONTEND.md` code-structure rule 2) that owns data extraction /
   formatting so the `.tsx` stays JSX-only, mirroring `-useOriginationTable.ts`.
6. Colocated `-*.test.tsx` / `-*.test.ts` unit tests.

Out of scope (deferred / separate sub-issues):

- Wiring Approve/Reject/Request-changes to the review + mint flow
  (`POST /v1/loan-book/submissions/{id}/review`, Trustee-key NFT mint). Buttons
  render **inert/disabled placeholders** this issue (Type-1 signing is a
  separate sub-issue). See Open Questions #1.
- Any backend change. `SubmissionView`, `CollateralValuationResponse`, and the
  `/valuations` endpoint already exist on `main` and stage.
- The nav badge count on the sidebar (tracked separately in tech-debt).

## Assumptions and Risks

- **`loan_id` for `/valuations` = `SubmissionView.id` (OQ#1, human-confirmed),
  BUT verified against stage this returns 404 for every current submission.**
  Confirmed live against `https://api.pipeline.stage.eqlab.net`:
  - `GET /v1/loan-book/submissions?chain_id=99000001` returns submissions with
    `id: 1, 2` (`status` `Rejected` / `Approved`).
  - `GET /v1/loan-book/{id}/valuations?chain_id=99000001` for `id ∈ {0,1,2,3}`
    → **HTTP 404** for all; `loan-book` summary shows `total_collateral: null`
    (no valuation anchors exist on stage at all right now).
  - Backend confirms the two id-spaces are distinct: the submissions PK `id`
    (`SubmittedLoanRow.id`, i64) is explicitly *not* the on-chain `loan_id`
    ("does not exist until the loan is drawn" — `loan_book.rs:206`); the review
    endpoint (`review_submission`, `loan_book.rs:427`) keys only on the
    submission `id` and never mints or records a `loan_id`; the `/valuations`
    handler parses `loan_id` as a `BigDecimal` on-chain id
    (`collateral_valuation.rs:175`) and 404s when no anchor row matches.
  - **Consequence:** the "no valuation yet" state (404 / `waterfall: null`) is
    the *default* rendered state today, not a rare edge. The page MUST treat it
    as a first-class, non-error state (see Implementation Step 6). Passing
    `SubmissionView.id` as the path param is correct per the confirmed answer;
    just do not assume a 200.
- `loan_data` is `serde_json::Value` on the wire — every nested read is
  defensive (`—` on missing/malformed), exactly as `-useOriginationTable.ts`
  already does. Reuse its `safeString` / `safeNumber` guard style.
- **Reuse, do not duplicate, the #813 types.** `SubmissionView`,
  `SubmitLoanRequest`, `EconomicsInput`, `LocationInput` live in
  `packages/trustee/src/api/useLoanSubmissions.ts` — import from there.
  Reuse `formatFullUsd`, `formatBpsRate` (`utils/formatUsd.ts`) and
  `formatMaturityDate` (`utils/formatDate.ts`). The Corridor arrow transform
  (`"PE-CN"` → `"PE → CN"`) is the #813 convention — reuse the same regex.
- **`SubmissionView` in the trustee TS port is missing the top-level
  `documents` field** that the backend `SubmissionView` serves
  (`loan_book.rs:235`, lifted from `loan_data.documents`). The Deal Details
  card renders a document list, so the port must add
  `documents: { name: string; uri: string }[]`. NOTE: on stage today
  `documents` is `[]` for submissions (only post-mint `loan-book` entries carry
  populated docs) — the card must render an empty/`—` documents state
  gracefully. See Open Questions #5.
- **Router navigation state is not durable across a hard refresh / direct URL.**
  TanStack Router `location.state` is lost on reload. If the user deep-links or
  refreshes, `loan_data` is absent. See Open Questions #3 for the fallback
  decision; the plan defaults to a refetch fallback.
- Figma uses `Besley` (display) for headings and `Inter` (body) — same token
  set as #813 (`var(--font-display)` / `var(--font-body)`). Card border color
  is the exact `rgba(56,55,53,0.18)` literal used throughout #813.
- The chips (`Your key · one click`, `NSR · Net Smelter Return`,
  `Awaiting your review`) and the two green banners are shown as static strings
  in Figma with no confirmed backend source for two of them. See Open
  Questions #4 — do not fabricate.
- Risk: the trustee app is auth-gated (`RouteGate`); the new route sits inside
  the authenticated shell automatically (all `routes/*` except `/sign-in`).
- Sandbox quirk: if `yarn workspace @pipeline/trustee test` breaks under the
  workspace runner, fall back to `node node_modules/.bin/vitest run` under
  Node 20 (per issue note).

## Open Questions

1. **Action buttons (Approve/Reject/Request changes).** Recommend rendering
   them as **inert/disabled placeholders** this issue (Type-1 signing + NFT
   mint is a separate sub-issue; no wired review call). Confirm inert vs. wire
   `POST /v1/loan-book/submissions/{id}/review` now.
2. **Valuation card is empty in practice today.** Because every current
   submission 404s on `/valuations` (verified on stage), the collateral card
   will render its "no valuation yet" state for all real data right now. Is
   that acceptable for this issue (render the INPUTS/waterfall/CCR as `—` /
   hide the waterfall, keep the card shell + freshness/footer), or should the
   whole card be conditionally hidden until an anchor exists? Recommend:
   keep the card shell, render `—` and hide the waterfall/CCR sub-rows.
3. **Direct-URL / refresh access (no router state → no `loan_data`).**
   Recommend a **refetch fallback**: on missing navigation state, call
   `useLoanSubmissions()` and select the submission whose `id` matches the
   `$loanId` route param (the list endpoint is already polled/cached); render a
   loading state meanwhile, and a "submission not found" state if absent.
   Confirm vs. the simpler "redirect to `/origination` if state missing".
4. **Banner / chip data provenance.** "All three mint invariants pass" and
   "Originator signature verified" (green banners) and the
   `NSR · Net Smelter Return` + `Awaiting your review` chips: is there a
   backend source, are they derived, or are they static design copy? No field
   in `SubmissionView` / `loan_data` carries mint-invariant or
   signature-verification results, and (per #813's resolved OQ) the valuation
   mode is not reachable pre-mint. Proposal, pending confirmation: render the
   `Awaiting your review` chip from `status === "InReview"` (derivable) and the
   `Your key · one click` chip as static; render the two green banners and the
   valuation-mode chip ONLY when a real source exists — otherwise omit them
   (do not fabricate a passing/verified state). Which of these are safe to show
   as static design copy vs. must be omitted?
5. **Fields the Figma shows that `loan_data` doesn't cleanly provide.**
   - Documents list: backend `documents` is `[]` for submissions on stage
     today (populated only post-mint). Render an empty state / `—`, or omit the
     documents block when empty? Recommend: render the block with a muted
     "No documents provided" line when empty.
   - `Start date` (Figma "10 Jul 2026"): map to
     `economics.origination_date` formatted via `formatMaturityDate`
     (day-month-year) — confirm this is the intended source (vs. `created_at`).
   - The heading / breadcrumb "<Originator> — <Commodity>": which originator —
     `SubmissionView.originator` (the authenticated submitter address, e.g.
     `GAMF...`, per #813) or `loan_data.originator` (the human name "Open
     Mineral")? Figma shows a human name, so **`loan_data.originator`** is the
     right source for the heading/breadcrumb/Deal-Details "Originator" row
     (distinct from the #813 table, which uses `SubmissionView.originator`).
     Confirm.
   - **Standard-goods layout** (`valuation_mode = StandardGoods`,
     `waterfall: null`): Figma only shows the MetalConcentrate NSR waterfall.
     What does the right column render for standard goods? Proposal: show the
     INPUTS the response provides, replace the NSR-waterfall sub-rows with the
     standard-goods computation the response exposes (`collateral_value`,
     `ccr`), and hide the concentrate-only lines. Confirm the exact standard-
     goods row set (there is no Figma reference for it).

## Implementation Steps

1. **Extend the trustee `SubmissionView` port** in
   `packages/trustee/src/api/useLoanSubmissions.ts`: add the missing top-level
   `documents: LoanDocumentDto[]` field (`{ name: string; uri: string }`) to
   match the backend DTO (`loan_book.rs:235`). Export a `LoanDocumentDto`
   interface. (Additive; does not change existing #813 behavior.)

2. **Add the valuation hook**
   `packages/trustee/src/api/useCollateralValuation.ts`:
   - Port the response types from
     `packages/api/src/routes/collateral_valuation.rs`:
     `CollateralValuationResponse`, `CollateralValuationInputs`, `MetalInput`,
     `PenaltyInput`, `Waterfall`, `Ccr`, and a `ValuationMode` string union
     (`"MetalConcentrate" | "StandardGoods"`). All money/number fields are
     strings (already human-scaled USD 2-dp); `waterfall`, `collateral_value`,
     `ccr`, and every optional input field can be `null`.
   - `useCollateralValuation(loanId: string | number, enabled: boolean)`:
     `useQuery` keyed `["collateral-valuation", chainId, loanId]`, `queryFn`
     `apiFetch<CollateralValuationResponse>(\`/v1/loan-book/${loanId}/valuations?chain_id=${chainId}\`)`,
     `chainId = ENV.STELLAR_CHAIN_ID`, `enabled` gated (skip when no id).
   - **404 handling:** `apiFetch` throws a plain `Error` on 404. Detect it
     (message includes "no valuation" / status not carried — set
     `retry: false` and expose a `notFound` boolean by catching in the hook, OR
     extend `apiFetch`/add a typed 404 the same way `ApiUnauthorizedError`
     exists). Prefer the minimal approach: treat any error from this endpoint
     as "no valuation available" in the view-model (Step 6) rather than a hard
     error banner, since 404 is the expected default today. Do not surface a
     scary error state for the expected pre-mint case.
   - Mirror `useLoanSubmissions` conventions (queryKey shape, bearer via
     `apiFetch`, no polling needed — or a modest `refetchInterval` matching the
     freshness chip's 60-min cadence is optional; default: no poll).

3. **Make #813 table rows navigable** in
   `packages/trustee/src/routes/origination.tsx`:
   - Wrap each row (`data-testid="origination-row"`) so the whole row is
     clickable and keyboard-activatable: add `role` stays `row` but add an
     accessible affordance — either `onClick` + `onKeyDown` (Enter/Space) +
     `tabIndex={0}` + `aria-label`, or an overlaid focusable element. Cursor
     pointer, hover affordance (subtle bg per token). Keep the existing status
     cell/button interactions from stealing the row click (the Review button is
     inert/`disabled` so no conflict; still `stopPropagation` defensively).
   - On activation: `useNavigate()` → `navigate({ to: "/origination/$loanId",
     params: { loanId: String(row.id) }, state: { submission } })`, passing the
     full `SubmissionView` for the clicked row. `-useOriginationTable.ts` must
     therefore also expose the raw `SubmissionView` per row (add it to
     `OriginationTableRow`, or return a parallel lookup) — currently it only
     returns formatted strings. Prefer adding a non-rendered
     `submission: SubmissionView` field to the row model.
   - Do NOT alter the Review button's inert appearance/behavior.

4. **Create the route file**
   `packages/trustee/src/routes/origination.$loanId.tsx`:
   - `createFileRoute("/origination/$loanId")`. Read the `$loanId` param and
     the navigation `state.submission` (typed). Use the layout:
     `<main className="mx-auto flex w-full max-w-[1200px] flex-col ...">`
     consistent with #813's page shell (Figma `Main` uses `px-[56px]
     pt-[39px] pb-[80px]`; match the #813 `max-w-[1200px]` container precedent
     unless Figma's `max-w-[1180px]` is preferred — use `1180px` per Figma
     node `4116:9293`).
   - The `.tsx` is JSX/styling only; all data extraction + formatting lives in
     the colocated view-model hook (Step 5).

5. **Create the view-model hook**
   `packages/trustee/src/routes/-origination-detail.ts` (or
   `origination.$loanId-detail.ts` colocated with a leading `-` so the router
   plugin ignores it):
   - Input: the `$loanId` param + optional `submission` from router state.
   - If `submission` is absent (direct URL / refresh): fall back to
     `useLoanSubmissions()` and `find(s => String(s.id) === loanId)`
     (Open Question #3). Expose a `state` discriminant
     (`loading | not-found | ready`).
   - Call `useCollateralValuation(loanId, enabled = submission is ready)`.
   - Map `loan_data` → display strings, all defensively guarded (reuse the
     `safeString` / `safeNumber` pattern from `-useOriginationTable.ts`; extract
     shared guards into a small `utils/` helper if it reduces duplication, but
     avoid over-refactoring #813):
     - Breadcrumb / heading: `\`${loan_data.originator} — ${loan_data.commodity}\``
       (Open Question #5 — use `loan_data.originator`, the human name).
     - Loan Terms: Facility `formatFullUsd(economics.original_facility_size)`,
       Senior `original_senior_tranche`, Equity `original_equity_tranche`,
       Offtaker price `original_offtaker_price`, Rate
       `formatBpsRate(senior_interest_rate_bps)` (+ " p.a." suffix per Figma
       "14.0% p.a."), Start date `formatMaturityDate(origination_date)`,
       Maturity `formatMaturityDate(original_maturity_date)`.
     - Deal Details: Originator `loan_data.originator`, Commodity
       `loan_data.commodity`, Corridor `loan_data.corridor` with the arrow
       transform, Governing law `loan_data.governing_law`; Documents from the
       new top-level `submission.documents` (empty state per OQ#5).
     - Valuation: map `CollateralValuationResponse` → the INPUTS rows and the
       NSR-waterfall→CCR rows. Render `—` for any `null`. Compute the freshness
       chip text and CCR "N% — above 130% ✓" label from `ccr.ccr_pct`
       (do NOT recompute the ratio client-side — it is served in `ccr_pct`;
       the ">130%" comparison is a threshold display, acceptable as a pure
       formatting of the served value — confirm in review this is display-only,
       not a derived metric per the [no-frontend-computed-metrics] rule).
